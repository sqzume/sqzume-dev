# 記事 URL に日付を含めず、分類はタグ 1 階層のみとする

記事の URL は `/blog/[slug]` とし、日付を含めない (`/blog/2026/09/my-post` としない)。
slug は英語で付ける。記事の分類はフラットなタグのみとし、カテゴリという上位概念は設けない。
URL とフロントマターのスキーマは、記事を 1 本でも公開した後に変更すると
被リンク・ブックマークの破壊や全記事の一括修正を招くため、実装前に確定させた。

## Considered Options

- **日付入り URL**: 時系列が URL から読めるが、古い記事を更新しても URL が古いままとなり、
  リダイレクト表を永久に抱える以外の解決手段がない。
- **日本語 slug**: URL がパーセントエンコードされ、共有時に長大で判読不能な文字列になる。
- **カテゴリ + タグの 2 階層**: 個人ブログの規模では運用負荷に見合わず、
  投稿のたびに「どちらに入れるか」で迷う原因になる。技術以外の記事は `雑記` タグで表現でき、
  2 階層と同じ効果が 1 階層で得られる。

## Consequences

- フロントマターは `title` `description` `pubDate` を必須、`updatedDate` `tags` `draft` を任意とする。
  `description` を必須にするのは、OGP と一覧の抜粋の品質を本文の書き出し任せにしないため。
- デザイン・配色・レイアウトは後からいくらでも変更できるが、URL とスキーマはできない。
  この非対称性が、プロトタイプより先にこれらを確定させた理由である。
