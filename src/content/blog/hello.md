個人サイトを作ることにした。ブログと自己紹介を兼ねたもので、ドメインは `sqzume.dev` を使う。

作り始める前に、決めないと後で高くつくものだけを先に潰した。逆に言えば、それ以外は全部後回しにした。

## 先に決めたこと

後から変更すると被害が大きい順に並べると、こうなった。

- **記事の URL**: 公開後に変えると、被リンクとブックマークが全部壊れる
- **フロントマターの項目**: 記事が増えてから足すと、既存の記事を全部触ることになる
- **タグの設計**: 後から統合や改名をすると、これも全記事が対象になる

URL は `/blog/[slug]` にして、日付を含めないことにした。`/blog/2026/09/hello` のような形式は時系列が読めて気持ちがいいが、古い記事を更新しても URL が古いままになる。リダイレクトを永久に抱える以外の逃げ道がない。

## 後回しにしたこと

色、書体、余白、レイアウト。つまり見た目のほぼ全部。

これらは CSS カスタムプロパティとして 1 箇所にまとめてあるので、気が変わったら値を差し替えるだけで済む。

```css
:root {
  --surface-0: oklch(0.17 0.008 265);
  --text: oklch(0.8 0.008 265);
  --accent: oklch(0.8 0.14 75);
}
```

この非対称性が面白いと思った。**デザインは何度でも変えられるが、URL は一度公開したら変えられない。** だから設計の順序は「見た目が決まっていないから作れない」ではなく、「見た目が決まっていなくても作れる部分から作る」になる。

### 具体的な順序

1. コンテンツのスキーマを定義する
2. 色をトークンとして定義する
3. 記事ページを組む
4. ホームを作り込む

ホームを最後にしたのは、いくらでも時間を溶かせる場所だからだ。ホームが未完成でも記事は公開できるが、逆はできない。

## ホスティング

Cloudflare Workers に置くことにした。静的サイトなら Pages のほうが素直に見えるが、2026 年現在は新規プロジェクトには Workers が推奨されている。静的アセットの配信が無償になり、Pages に留まる理由が価格面から消えた。

将来 OGP 画像を動的に生成したくなったときに、ホスティングを移さずに済むのも大きい。
